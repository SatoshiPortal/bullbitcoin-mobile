## Non-negotiable acceptance boundaries

- Full account-key matching, not fingerprint-only ownership. Importing a descriptor does not restore spending keys or bypass timelocks.
- The money-backup encryption key is distinct from the distributed metadata/descriptor backup words. Local money-key derivation needs a matching local seed and the selected backup file; PIN recovery uses the server.
- Public destinations carry only password-encrypted vault descriptors, never metadata or xpub-decryptable BIP138. No fee-paying publication without transaction review and approval.
- Neither stack has shipped. Preserve published upstream schema compatibility; do not build migration machinery for unshipped prototype states without evidence.
- No unrelated feature fixes, new orchestration framework or new private-key storage mechanism. Reuse established components and use cases.
- An implemented screen is not evidence of a working backup transport. Record remaining integration blockers honestly; do not mark the branch merge-ready until required checks actually pass.

## Native implementation checkpoint

Implemented on the consolidated distributed branch:

- One BullVault settings entry. Existing vault cards appear first, identified by the wallet fingerprint and available creation/recovery dates. The selected vault owns Policy, Keys, Backup & recovery, Renew, Import cosigner key, Register vault on another device and Sign PSBT. Use BULL as signer opens the existing signing-key export, not an unrelated signing flow.
- One reusable spending-policy component, shared by vault inspection and the restored-vault result. Separate Keys inspection reuses the existing signer component, external device selector and full origin-qualified account-key Copy/QR. Neither inspection screen has the removed bottom actions.
- Actual per-account-key availability checks. A persisted signer label or four-byte fingerprint is not proof of access. Passphrase-protected keys are explicitly reported as requiring a passphrase, not as verified unlocked keys.
- A protected cosigner import route, with the approved warning before entry and clarification that import does not move funds or bypass a policy. It verifies complete account keys before adding ownership, retains the canonical mnemonic in the existing encrypted seed store, and never persists the supplied passphrase. It does not change the default wallet.
- Combined Backup & recovery with full-descriptor QR/text, descriptor-only file export, saved-copy verification and printable kits. Successful manual file/QR/paste read-back and actual metadata-server fetch/decryption can advance independent last-tested dates. Copying, exporting, printing, selecting a destination, a failed attempt or a mismatch cannot.
- Real local PDF generation for Mobile, Cold and Inheritance kits, plus the second Cold key when Ben's Extra protection is selected. The PDF contains the entire descriptor, a dedicated large QR page, actual UTC recovery dates and blank fields for handwriting. Mobile/Cold have only a passphrase hint; Inheritance has the optional passphrase line and personal message. No mnemonic or passphrase is read into the PDF generator.
- Creation and renewal require an actual matching descriptor action. Checkbox-only confirmation is rejected at the use-case boundary; copy, scanned/pasted read-back or file import must supply the matching descriptor. This setup acknowledgement remains separate from a successful backup recovery test.
- View Backup Key offers local file derivation and PIN/password + server retrieval. Both require the selected encrypted money-backup file. Local derivation validates the supported historical file path, tries existing canonical seeds and authenticates decryption before revealing the key. It does not contact the server, restore a wallet, write a seed or update backup-test dates. Neither route exposes key processing before authentication and capture protection complete.

### Review findings fixed in this change

1. **Birthday-dependent verification identity:** `BullVaultPolicy.id` incorporates optional birth height, so an identical descriptor imported with a different birthday could lose its visible verification history. Receipts are now keyed by canonical public descriptor plus network. A regression test enriches the birthday without resetting the receipt.
2. **Grouped passphrase and canonical keys:** Ben can put the passphrased everyday key and the unpassphrased delayed Mobile recovery key in one normalized signer. Import now checks each account against its correct derivation and marks only the matching passphrased key IDs as requiring a passphrase. Wrong words or passphrase never write storage.
3. **Private-storage inspection failure:** a missing/unavailable signing seed must not hide the public policy or prevent descriptor export. Inspection now retains the public view and reports unavailable key access.
4. **Reveal lifecycle:** backgrounding could leave a key-reveal modal on the navigator. The reveal page now blanks its value and dismisses the modal and page; the parent gate discards the private flow and requires authentication again. Capture protection disabled by the user is a closed gate, not permission to reveal.
5. **Malformed stored descriptor / damaged receipt:** parser failures return a typed failure rather than leaving a loading screen unresolved. A corrupt verification receipt does not prevent exporting the actual descriptor, and a failed history write cannot produce a successful test result.
6. **Duplicate scanner delivery:** scanning callbacks are one-shot so a repeated camera result cannot pop multiple routes.
7. **Printable handwriting fields:** visual PDF inspection found a passphrase label separated from its writing line by a page break. The complete handwriting block is now inseparable during pagination.
8. **Duplicate warning:** removed the now-unused Backup Settings key-warning widget. RecoverBull owns the single warning before reveal; the deleted duplicate remains recoverable from Git history. Removed unused new localization keys for buttons that are not implemented.
9. **File-picker cancellation:** the installed app displayed “Failed to select vault” after the user simply dismissed Android's file picker. Cancellation now has a distinct result and returns without an error, loading indicator, derivation, network retrieval or test-date update. Foreign picker exception payloads are also excluded from logs and failure values. Regression tests cover all three selecting flows and malicious exception text.
10. **Dates without years:** native inspection found that the vault card and shared backup-test component used a date formatter that omitted the year. Both now include the year. The shared component still serves mnemonic and descriptor backups, with narrow-screen/large-text coverage; there is no separate BullVault date design.

### Known limits of the implemented routes

- Cosigner import crosses existing secure seed storage and SQLite ownership storage; they are not one transaction. If ownership attachment fails after seed storage succeeds, the encrypted canonical seed can remain on the device and a retry can attach it. The pre-entry warning discloses retention. Do not delete that seed on failure without checking whether another wallet already uses it.
- “On this device” describes verified key availability, not proof that the current chain conditions permit spending. Existing signing/PSBT validation remains authoritative. Passphrased keys are not reported as unlocked merely because they were imported.
- QR/full-text descriptor display is public wallet information, not a spend credential; it nevertheless exposes wallet privacy. Completed paper kits do contain spend credentials and must remain offline.
- Existing development-only setup confirmations are not migrated or given a compatibility schema. Neither feature has shipped. New create/renew confirmations must use the actual descriptor-action boundary.

## Remaining production integration — not completed by these UI commits

The full distributed-backup product is **not merge-ready**. These are actual missing connections, not optional polish:

1. **One words-derived metadata credential:** production `wallet_backup/domain/usecases/resolve_wallet_backup_key_usecase.dart` still uses raw reserved BIP85 entropy, and `wallet_backup/domain/wallet_backup_protocol.dart` uses the older Nostr identity. `portable_backup/data/backup_password_material.dart` has a separate words/HKDF encryption and Nostr derivation. Merely displaying its 12 words would falsely imply those words can retrieve/decrypt the production metadata backup. Align writer, authentication, lookup, export and recovery with independent vectors before exposing that claim. There is no approved extra password-encrypted descriptor record on the server.
2. **Private BIP138 server contract:** the inspected backend has the existing metadata record API, not the independently retrievable cosigner-key descriptor records required by the locked design. A caller providing the approved eligible public account key must be able to find and decrypt that private record without being asked for another secret. This needs matching backend/client implementation and end-to-end verification; an unavailable endpoint must not be invented in the app.
3. **Password-only public destinations:** portable Nostr and Bitcoin code remains outside production feature registration. Wire only password-encrypted vault descriptors to those destinations. Existing xpub-decryptable BIP138 publication prototypes must not be exposed as the approved public backup buttons.
4. **Backup destinations and password UI:** Additional backup protection after the mandatory descriptor action; independently selected server/Nostr/Bitcoin procedures and results; protected backup-word display in Data Backup and Vault settings; and fee review/explicit approval for Bitcoin publication remain to be connected.
5. **Recovery landing and all manual paths:** automatic server, Nostr and Bitcoin discovery must continue independently and restore all valid vault generations. Manual descriptor, cosigner public key, magic backup words and Mobile cosigner key must work independently; supplied BIP138 file + cosigner key also needs its local route. Descriptor import must remain possible with no private key and must not apply unrelated recovered metadata.
6. **All five verified-source histories:** only manual and metadata read-back currently have real operations behind the shared timestamp rows. BIP138, Nostr and Bitcoin remain untested; Check again currently checks metadata, not all five transports. Add source-specific actual fetch/decrypt/match paths before claiming comprehensive recovery verification.
7. **Network/lifecycle proof:** production Nostr publication/fresh-app fetch, private BIP138 with every eligible cosigner, testnet4 publication and discovery after spending the marker, interrupted broadcasts/retries, renewed generations and actual fresh-emulator recovery still need end-to-end tests. No paid transaction, public descriptor publication, backend deployment or production backup mutation was performed in this work.
8. **Vault signer-device metadata round-trip (existing integration gap):** `build_wallet_backup_snapshot_usecase.dart:75` removes vault wallets from the generic definitions section, but `bullvault_recovery_package_codec.dart:104` serializes no per-key device/registration metadata. The vault section reads that package plus the wallet label (`data/bullvault_backup.dart:65`). Consequently, changing an external signer's device on the Keys page is persisted locally and dirties the definition revision, but that device choice is absent from the recovered vault package. Preserve the approved vault-section ownership while adding a narrow public-signer metadata round-trip; do not restore private ownership claims or duplicate the whole vault into generic definitions. The descriptor/spending policy remains recoverable without these device labels.
9. **App-wide settings reorganization:** BullVault is grouped within the existing Wallet settings and its selected-vault hub is implemented. The broader five-section settings architecture and the requested full Wallet and Bitcoin ordering are not implemented by these commits. Legacy BIP85 settings still need to be reconciled with the production backup credential work, not removed before its replacement works.

No unrelated Payjoin, send, core signing, derivation profile or database migration was changed during this UI work. The existing prototype code remains available on this branch for the next integration step; it is not evidence that the production app exposes those capabilities.
