# RecoverBull

RecoverBull owns encrypted-backup workflows, provider access, local certification and advisory attempt monitoring. Secrets alone seals, inspects and imports wallet material. The feature never receives a mnemonic and never uses secure storage directly. Consumers import `bull_recoverbull.dart`; owner adapters implement its wallet, environment, permission and per-flow route ports.

The foreground composition mounts `RecoverBullFeature`, installs its route/localizations and displays its alert overlay below app unlock. It invokes `facade.checkAtColdStart()` once per fresh process. Resume does not check. There is no background entry point, scheduler or notification integration, and there will not be one: a background task cannot run Tor (iOS gives about 20 s, less than a Tor bootstrap), so monitoring stays in the foreground. Backup verification also reconciles the status returned by the counted fetch. Explicit service diagnostics use a separate owned route without polling attempt telemetry.

Consent is granted only for the configured server shown to the user. Preferences stores the live consent and its revision by runtime family; RecoverBull uses the revision to reject stale operations. Monitoring defaults on after consent; the existing switch opts out. Created, tested and restored vaults are enrolled, alongside vaults discovered through the signed-in Drive abstraction. Drive discovery is silent, account-scoped and paginated. User selections and deletion confirmations expire when the account changes. Automated tests use fakes, not a Drive account.

The standalone v1 history is copied to the encrypted owner database before runtime admission. The old files remain intact. The production server uses the configured default rather than a migrated URL; Preferences takes ownership of the historical consent through the permission-only migration entry point. Regtest starts with a separate, clean encrypted store.

The owner stores backup timestamps, digest-only attempt attribution and persistent generic alerts. The inventory import preserves four historical backup facts for each wallet usage; it projects them per secret without discarding differing wallet rows. An old verification flag cannot certify a vault: vault-specific verification stays unknown until Secrets inspects it against the captured wallet context.

Before any counted fetch or trash, a durable own-operation marker must commit, even with monitoring disabled. FULL/ENOSPC, corrupt/unreadable metadata and other write failures produce distinct typed failures. Failed admission sends no counted request. Manual vault-key recovery remains available without opening this database; a successful import and a failed metadata write are reported separately. Corrupt or future-schema files are preserved, never silently replaced. If opening the database fails at startup, restart after correcting the storage problem; ordinary write failures on an open database can be retried in the flow.

Telemetry is advisory. Only unexplained activity or targeted lockout creates an alarm. Outages, stale projections and unresolved own requests produce unknown coverage. A vault absent from a published snapshot has had no request yet and is monitored from zero, and every request in a window or collection that started after the last observation is new; only own requests explain either. Alerts survive restart, contain no identifiers or counters, and require no automatic action. Delayed replies and cancellation never erase durable own-operation allowances.

Run the pinned SDK through root make targets: `make deps`, `make recoverbull-build-runner`, `make recoverbull-translations`, `make recoverbull-drift-migrations`, and `make checks`. Generated Dart and localizations follow the repository's existing ignore policy; the JSON schema snapshots are versioned. Only a full Xcode build validates iOS integration.
