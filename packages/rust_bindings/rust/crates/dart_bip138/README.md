# dart_bip138

BIP138 v1 items through the aggregate `rust_lib_bull_sdk` FRB bridge. Only public descriptors cross this API. Dependency features deliberately exclude legacy v0, base64, descriptor/policy backup serde, devices and CLI support.

`bip138_encrypt` requires the supplied public-descriptor set to equal the parsed descriptor set embedded in bare BIP380 items and BIP139-1 `bip380` / `multi_bip380` accounts. Comparison ignores descriptor checksums and duplicate entries through parsed canonical descriptors. Keys and origin paths are then extracted from the embedded descriptors together, using upstream NUMS and cross-descriptor exposed-root exclusion. A caller cannot encrypt a BIP139 export using descriptors omitted from that export. Unsupported BIP139 account types and BIP388 policy items are rejected by the writer. Opaque vendor/text/other BIP items must not introduce additional descriptor or policy material; interpreting their schemas belongs to their owner. This binding validates descriptor consistency, not the complete BIP139 schema.

`bip138_excluded_keys` reports exclusion categories without returning key expressions. The writer refuses an empty eligible key set. The reader accepts public descriptor candidates (including bare xpub roots), returns null only if none authenticates, and reports an error for malformed envelope framing or authenticated malformed plaintext. Unknown non-critical content types are skipped as required by BIP138. Only the first encrypted payload is read; trailing extension bytes are ignored.

Limits apply on both write and read: envelope including padding 4 MiB, item 2 MiB, BIP329 item 1 MiB, vendor item and tag 512 KiB. Descriptor inputs are limited to 255 descriptors, 64 KiB each and 4 MiB total. Errors contain fixed labels only, with no foreign error strings, keys, descriptors or payload bytes. There is no input logging.

The decoder uses the bounded low-level `decode_v1` path, never the metadata helper that scans appended encrypted payloads. The latter is unnecessary for this API. Authenticated plaintext passes through the checked low-level content decoder, with item limits and UTF-8 text validation applied before returning to Dart. See tests for malformed framing, overflow lengths and authenticated malformed plaintext. Encryption uses the upstream OS entropy adapter; its entropy-failure `expect` is not on a decode path.
