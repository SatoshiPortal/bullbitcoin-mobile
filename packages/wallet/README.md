# Wallet

Shared native-wallet ownership is being extracted here. `wallet.dart` is the public entry point. `WalletStoragePaths` preserves the installed BDK filename, LWK root, and parent-cache sidecar; the host supplies its documents directory through `WalletStoragePathsPort`.

`WalletLocator.bdkElectrum` and `WalletLocator.lwkElectrum` construct watch-only native sources as `WalletTransactionSourcePort`. The host injects them into `WalletTransactionSyncFacade`; transaction_sync owns coordination and publication without depending on a native SDK. Source algorithms, resource scopes, and tests move together.

`Wallet`, `Network`, `ScriptType`, the signer enums, `WalletBalances`, and `TransactionSignatureStatus` are exported domain values. The sealed `WalletFailure` family also lives here; its variants and recovery semantics are unchanged. Host presentation extensions in `lib/wallet_presentation_adapters.dart` retain the existing labels and localization without making the package depend on app UI. The generated `$WalletCopyWith` contract is exported for consumers whose Freezed states contain a wallet.

## Extraction status

The foreground BDK/LWK datasources, their native resource owners, and SDK models now live here alongside the watch-only source adapters. Their algorithms and LWK status-conflict cache recovery are preserved. The app resolves Electrum privacy policy and supplies `WalletConnectionPort` values. `BdkElectrumCache` is private; there is no cache barrel. Foreground and headless use the same native opening and Electrum request implementations. Datasource/model construction exports remain for shell composition and the held secrets/Payjoin adapters on this develop-based branch; the ordinary Transactions consumer uses domain details only.

Tests cover opening and synchronizing a copied BDK installation at its legacy path without changing the original fixture, real offline BDK reconstruction, deterministic loopback Electrum scenarios, parent-cache parity, source cleanup, and LWK mapping. The live-network discovery test remains explicitly opt-in. The opt-in `lwk_installed_wallet_network_test.dart` creates a real empty Liquid testnet cache through the native SDK, copies its legacy directory tree, then reopens and synchronizes the copy through the package. It checks the receive address and hashes the original files to detect unintended writes. This proves cache reopening and synchronization, not funded-history parity or recovery from an incompatible update.

Run the Liquid fixture with `RUN_LWK_NETWORK_FIXTURE=1` and `FRB_DART_LOAD_EXTERNAL_LIBRARY_NATIVE_LIB_DIR` pointing to the directory containing the pinned SDK's native library: `fvm flutter test packages/wallet/test/lwk_installed_wallet_network_test.dart`. Build that library from the resolved `bull_sdk` checkout using its `rust-toolchain.toml` and `cargo build --locked --lib -p rust_lib_bull_sdk`; keep build output outside the app repository. The test defaults to the app's public Liquid testnet endpoint; `LWK_FIXTURE_ELECTRUM_URL` can select another Liquid testnet server with a trusted TLS certificate. Network access is opt-in so offline checks do not depend on a public service.

`DescriptorDerivation` owns the existing native Bitcoin and Liquid descriptor derivation. The package's metadata derivation consumes this capability; SDK keys and descriptors remain internal to the implementation.

`WalletOriginCodec` owns the legacy origin encoding and decoding used for wallet identifiers and BIP329 labels. It preserves script wrappers, network and account paths, fingerprint casing, and parsing failures; the host's metadata and labels adapters consume it through the barrel.

`WalletXpubImport.derive` owns watch-only xpub metadata derivation, including legacy version-byte normalization, origin identity, descriptor pairs and import defaults. It returns only `WalletMetadata`; BIP32 objects stay internal. `WalletSeedDerivation.derive` owns the matching seed-derived metadata path. Creation inputs are ephemeral parameters, never stored or returned; the host translates its existing seed entity at the call site. The legacy missing-mnemonic exception and Liquid descriptor derivation remain unchanged. Characterization hashes cover all script/network combinations; run the six offline native Liquid cases with `RUN_LWK_METADATA_FIXTURE=1` and the pinned native-library path configured, alongside the default Bitcoin and bytes-only tests.

`WalletPsbtInspection` reads size, fees, and destination amounts from supplied Bitcoin PSBTs without opening wallet files or loading keys. The native implementation stays inside wallet; fixture tests preserve repeated-output aggregation, network address encoding, and parse failures.

`BitcoinWalletRepository` and `LiquidWalletRepository` own spend construction and source-session coordination. `WalletSigningPort` supplies operation-scoped signing without returning secret material; the host adapter resolves the legacy seed store and delegates native work to `WalletSigningOperations`. Bitcoin signing retains its second metadata read under the source gate. `WalletCoinPort` exposes only the outpoint needed for coin selection, keeping feature labels outside the package.

`WalletRepository` owns wallet metadata/balance operations and the existing synchronization lifecycle. `WalletSyncConnectionPort` delegates server selection, privacy policy and safe failure classification to the host; it does not export server lists. Wallet creation accepts ephemeral `WalletCreationSeed` inputs, and environment filtering takes a mainnet flag rather than a settings entity. The existing foreground observation callback is published by transaction_sync pending its consolidation with snapshot publication.

`WalletUtxoRepositoryImpl` maps SDK UTXOs into label-free `WalletCoin` domain values and preserves global outpoint freezing. The Coins feature decorates those values with output, transaction and address labels through its own repository; Labels reaches that projection through a shell adapter, without importing Coins. The original label lookup order and source coordination are covered by consumer parity tests.

`WalletAddressRepository` owns native address derivation, revelation and address history under the source gate, returning label-free `WalletAddressRecord` values. An injected reservation capability preserves the existing system-reserved address skipping. The Address View feature decorates addresses through callbacks inside that same gate, preserving the original lookup order, timestamps and failure propagation without importing Labels into wallet.

Shared wallet use-cases live with the package contracts. App-dependent wallet creation, backup checks and deletion orchestration belong to the Wallets feature; label-aware address and coin use-cases belong to Address View and Coins. Bitcoin send preparation belongs to Send. The host composes these services in `lib/wallet_setup.dart`; no wallet code remains under `lib/core/wallet`. Sync stream wrappers retain their legacy projections until the normalized snapshot cutover.

Persisted BDK wallet construction is shared by the foreground facade and transaction source through BdkWalletSession; LWK construction uses LwkWalletSession. The native Electrum request implementations are private to wallet and shared by both callers. Caller-specific batch sizes, lookahead, fallback/error mapping, cache persistence order and Liquid recovery remain unchanged during this extraction. Transaction lists are published through the shared snapshot reader. Removing the remaining signing-related construction exports belongs to the secrets-based integration.

Foreground transaction lists now use `WalletSnapshotReader` to reconstruct and publish a local `transaction_sync` snapshot under the already-held source session. Native sync and its recovery policy still run before that read when explicitly requested; local reads contain no endpoints and perform no network request. Fresh foreground wallets retain local empty-store initialization, while the default background sources still report missing local state. The Transactions feature maps explicit display evidence and enriches labels after the source operation; missing evidence fails the read instead of becoming zero or empty history. Exact transaction lookup remains targeted, and only an explicit Liquid detail request obtains an ephemeral unblinded URL.

`WalletTransactionReader` owns the coordinated read and optional synchronization formerly performed by the Transactions feature. Its signatures use WalletMetadata and WalletTransactionDetails, with sealed input/output details; no SDK model crosses that read boundary. Native exact reads map their internal models into these values, while lists project normalized snapshots. The ephemeral Liquid URL exists only in an explicit exact-detail result. The feature owns labels and UI entities; it no longer holds native datasources or a sync lock.

The public barrel uses explicit symbol lists. Native opening facades, the Electrum cache, scan/confirmation/prevout helpers, and local-initialization controls are not exported. Native sessions cannot be supplied through the public ownership-check methods. The package retains foreground error/recovery and sync-stream behavior; the shared request helpers own the actual BDK full/revealed scan and LWK scan, while callers keep their existing fallback, batch-size and persistence boundaries.
