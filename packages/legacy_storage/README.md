# Legacy storage

`package:legacy_storage/app_database.dart` exposes `SqliteDatabase` and the types used by the remaining legacy readers. The application database keeps its schema-16 table declarations, snapshots and seeds in this package. Run `make drift-migrations` from the workspace root to regenerate the migration helpers. App-level cutover tests exercise the historical database with the encrypted owner stores.

## Cutover coordination

`coordination.dart` owns the temporary split-v1 protocol. Composition supplies an inert legacy database factory, source path, the complete expected-owner manifest and the participants available in this development slice. The package has no dependency on an owner. The legacy constructor receives an owner-controlled worker executor; temporary and runtime connections explicitly acknowledge native closure before their admission is released. Composition also lists destination families so an orphaned owner store cannot be mistaken for a new installation. Each participant opens only under an admission and owns its mapping, receipt and close operation.

The marker records installation history, per-owner provenance and the owners that have reached their first verified receipt. Version 2 requires an explicit list of admitted owners; only the provisional version-1 development marker can omit it. A fresh pilot still marks unported owners as legacy before the source is established and before any runtime is published. Later slices import the data those owners accumulated. Under exclusivity, the foreground verifies the receipt and closes the owner before publishing its admission milestone. From that point on it never prepares that owner again: an absent owner family fails closed, and even a present family must still prove its receipt under shared admission. Missing data is never rebuilt from stale legacy copies. A flushed temporary marker can be recovered under exclusivity. Errors after replacement require re-reading state, not assuming the old marker survived.

The lifecycle gate uses independently opened native `flock` descriptors on a stable sentinel, with nonblocking bounded acquisition. Foreground migration requires exclusivity. Temporary handles close before release; runtime then acquires a shared lease and revalidates. Each live handle belongs to the admission. Failed closure retains the handle and lease in quarantine; no timeout or generic cleanup callback unlocks it prematurely. `retryQuarantined` can retry confirmed closure. Background startup uses the same gate and maps incomplete admission or cleanup to retry.

The encrypted owner transaction is authoritative: row verification and the fixed receipt commit together. The external marker is never a substitute for a receipt. S1a implements no retirement or deletion, and refuses retirement states. Unported owners keep their historical file active; the complete production migration ships in one release and final retirement requires all obligations to be verified. Existing historical snapshots remain immutable.

Linux tests cover independent descriptors, isolates, processes, process death, marker recovery and failed-close quarantine. A process kill is not a power-loss test. Android/iOS native locking, encrypted WAL lifecycle and OS backup policy still require platform validation before release.
