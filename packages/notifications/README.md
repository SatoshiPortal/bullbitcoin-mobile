# Notifications

`notifications` owns generic local-notification delivery for the application. It does not know wallet transactions, routes, background workers, or shell composition.

Events are persisted in an SQLite outbox keyed by a stable event ID. Enqueue is idempotent. The outbox starts with a deterministic 31-bit SHA-256 candidate and probes persistently until it finds a unique platform ID; this avoids claiming that the hash alone is unique. Delivery is at-least-once: an ownership token prevents simultaneous claims, while an expired lease permits crash recovery; a crash after `show` and before marking delivery retries the persisted platform ID for platform-side replacement/deduplication.

`reconcileTopic` receives a stable topic ID and its complete current observation. The first observation inserts a silent, delivered baseline and atomically marks the topic initialized. Later observations insert only previously unseen events as pending. Topic markers, event inserts, and platform-ID allocation share one SQLite transaction, so repetition and reopen are safe; concurrent connections cannot create duplicate events. Reconciliation is intentionally generic and has no wallet knowledge.

The gateway hides `flutter_local_notifications` from the public contract. `initialize` never requests notification permission; the consuming shell can call `requestPermission` when its foreground UX is ready. A tap or launch payload is persisted by the callback passed during `initialize`; if persistence fails, the facade retains the payload in memory and the shell can call `retryUnpersistedResponses` on resume/init. Successfully persisted responses are consumed transactionally once across database reopenings, while platform callbacks and delivery remain at-least-once. If storage is unavailable and the process dies, no durable guarantee is possible. Payloads contain only the package's stable destination value; unknown values are rejected.

Schema version 1 is the first delivered schema for this package. No compatibility code is included for the unreleased intermediate development schema. The short SQLite busy timeout is 250ms; callers should retry rather than blocking indefinitely. Platform channel setup, Android desugaring, notification channels, permissions, and native lifecycle wiring belong to the first consuming shell. Background callbacks must use the plugin's documented top-level callback mechanism and forward durable data through this outbox; this package assumes no shared memory between isolates. Persisted platform IDs remain stable after crash/reopen while this outbox database is retained; deleting and reconstructing the database intentionally loses that allocation history.
