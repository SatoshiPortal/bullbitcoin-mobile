# Notifications

`notifications` owns generic local-notification delivery for the application. Its wallet identity helper accepts the typed WalletKey contract; delivery does not depend on native transactions, routes, background workers, or shell composition.

Events are persisted in an SQLite outbox keyed by a stable event ID. Aggregate reconciliation is idempotent. The outbox starts with a deterministic 31-bit SHA-256 candidate and probes persistently until it finds a unique platform ID; this avoids claiming that the hash alone is unique. Delivery is at-least-once: an ownership token prevents simultaneous claims, while an expired lease permits crash recovery; a crash after `show` and before marking delivery retries the persisted platform ID for platform-side replacement/deduplication.

`reconcileTopicsAndEnqueue` receives stable topic IDs and current observations. It skips topics without a foreground baseline. For initialized topics it records previously unknown payments and enqueues one aggregate, atomically with platform-ID allocation. Repetition and reopen are safe; concurrent connections cannot create duplicate events.

The gateway hides `flutter_local_notifications` from the public contract. `initialize` never requests notification permission. `NotificationPermissionsFacade` reports, requests and opens the system settings for the permission; it needs no outbox, so a startup wizard can use it before the app is initialized. A tap or launch payload is persisted by the callback passed during `initialize`; if persistence fails, the facade retains the payload in memory and the shell can call `retryUnpersistedResponses` on resume/init. A topic is initialized only by `recordObserved`, called by the sync-completion consumer with the sync’s own discoveries and a separate `baselineEvents` history. The initial history is persisted without `seen_at`; existing baselines never absorb later payments. Only discoveries from a sync completed in the foreground are marked seen, never a snapshot re-read after a background revision: reconciliation skips a topic nobody recorded yet (it never takes a silent baseline behind the user's back), payments recorded as seen are never announced later, and a pending aggregate whose payments have all been seen is dropped. `deliverPending` checks that the OS shows the app's notifications first; while it does not, pending notifications are settled without being shown and the call returns `NotificationsPermissionDeniedFailure`, so granting the permission later never replays a backlog. Successfully persisted responses are consumed transactionally once across database reopenings, while platform callbacks and delivery remain at-least-once. If storage is unavailable and the process dies, no durable guarantee is possible. Payloads contain only the package's stable destination value; unknown values are rejected.

The outbox schema starts at version 1 and is created in a single transaction; versions above 1 are refused. No compatibility code is included for unreleased intermediate development schemas. The SQLite busy timeout is 5 s; callers should retry rather than blocking indefinitely. Platform channel setup, Android desugaring, notification channels, permissions, and native lifecycle wiring belong to the first consuming shell. Background callbacks must use the plugin's documented top-level callback mechanism and forward durable data through this outbox; this package assumes no shared memory between isolates. Persisted platform IDs remain stable after crash/reopen while this outbox database is retained; deleting and reconstructing the database intentionally loses that allocation history.

The outbox is durable, non-rebuildable state: deleting it loses seen baselines, pending deliveries and deferred destinations. It must not be treated as a cache. WalletSyncCompletion and WalletPaymentObservationAdapter belong to this package. The writer binding captures completion-time foreground visibility and records the completion before returning success to its caller; snapshot/revision reloads never invoke this adapter. This package is not activated by this phase.
